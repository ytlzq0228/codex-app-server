# 会话恢复与错误诊断修复

## 已实施

- Codex 接入已有的上下文恢复路径。失效工具结果必须匹配持久化的 Key、接口、会话和历史检查点；新的用户轮次可放弃旧的等待状态。恢复轮禁用工具，不把历史工具调用重新执行。已被另一请求接收的结果仍不能被取消。
- Codex、Claude、Gemini 的失败工具续接保留经过校验的历史，允许后续进行仅使用上下文的恢复。
- 跨节点取消使用由操作类型、Key、会话和响应检查点确定的操作标识。取消任务独立于入口 HTTP 请求存活；重复请求及状态查询复用原任务。入口确认完成后，在自身事务中删除路由。连接超时、取消确认超时、执行冲突、未知状态分别返回明确错误码。
- Claude 的传输异常、无终态、无输出成功、无效事件及进程中断分别分类。没有新增可能重复执行工具的自动重试。
- 模型列表、模型详情与执行路由使用同一账号兼容规则。默认拦截已观察到不支持 gpt-6.1-sol 的 chatgpt 认证账号，可通过 CODEX_GATEWAY_MODEL_AUTH_RESTRICTIONS 覆盖规则；不自动替换模型。此规则仅代表明确配置的不兼容情况，不是上游全部模型能力的自动发现。
- 图片搜索保持明确拒绝，并说明可改为 search_content_types: ["text"] 或省略该选项。不将混合搜索悄悄降级成文本搜索。
- UsageRecord 的 conversation_evidence.diagnostic 保存异常类型、文件名、函数、行号、节点和可选发布标识。不会保存异常消息、局部变量或完整文件路径。随数据库审计保留，独立于容器日志生命周期。CODEX_GATEWAY_RELEASE 可用于提供发布标识，未设置时为 unknown。

## 验证

- 独立临时 PostgreSQL 上，恢复、取消、模型映射、搜索、Claude、Gemini、路由与 API 相关测试共 280 项通过。
- 新增诊断持久化测试后，诊断与模型保护专项 5 项通过，其中包含流式与非流式失败经新数据库连接读回的校验。
- 测试环境原有版本的真实请求对照：Claude 普通对话、三个工具声明、结构化输出加三个工具均完成；历史报错模型在合成对照请求中也完成。
- 测试环境原有版本的真实工具对照：两路并行 Claude、一路 Gemini 均接收模拟失败结果后继续回答，未再次调用工具。
- 上述真实对照不等同于本次代码已经部署后的验证。当前修复尚未部署。

## 未闭环与限制

- 历史集中 Claude Chat 502 尚未复现，不能认定其根因已消除。已核查样本形状，并补齐可持久化诊断；需要在新版本实际承接相同问题时根据明确异常链定位，或获得可稳定复现的请求。
- Claude execution_failed 是上游失败分类，不能保证所有上游失败都消失；本次重点补齐失败后恢复与诊断。
- 取消状态保存在所属网关进程内，有界保留。网关重启后的状态查询可返回未知，必须重新提交取消请求并重新验证执行身份；不能把超时或未知状态当作已取消。
- 本次未改变 Claude 客户端版本策略，未扩大 Worker 容量。
- 未修改或发布工作区已有的 service-key 功能；与其共享文件的修复需按实际 diff 审阅。
