# 用户服务与计费

## 页面

- `/account`：个人 Key、刷新 Key、修改或设置密码。
- `/admin/users`：创建用户、角色和邮箱维护、禁用、重置密码、查看 Key 状态。
- `/admin/api-keys`：查看归属用户、从已有用户中选择新的归属、刷新密钥。
- `/admin/google`：配置 Google OAuth Client ID、Client Secret、回调地址、允许的邮箱域及启用状态。配置保存在 `google_auth_config` 表，立即生效。Secret 不回显，空白提交保留原值。
- `/usage`：按请求 ID、模型、状态、UTC 日期查询详单。普通用户只能查看请求发生时属于自己的记录，管理员可查看全部。
- `/admin/finance`：模型价格配置，支持行内编辑。
- `/admin/reports`：按月或全部时间，以最新价格汇总用户/Key 和 Worker 用量金额，维护订阅成本，显示金额差额。此版本仅核算金额，不执行支付、扣款或预算限制。
- `/debug`：浏览器携带输入的 Key 调用本站 Responses、Chat Completions 或模型列表，显示 HTTP 状态、耗时和实时响应。

## 身份和会话

`users.username` 为主键。密码使用 PBKDF2 哈希；Google 身份按 `google_sub` 唯一关联，不根据可修改邮箱自动合并已有本地账户。Google 新用户默认 `user`，邮箱作为初始用户名，冲突时生成独立用户名。

`superadmin` 可管理全部用户；`admin` 只能管理普通用户，但可管理 Key、价格、Google 配置及 Worker；`user` 只能访问个人服务。禁止通过用户管理降级或禁用自己。管理员创建或重置密码生成随机初始密码，用户必须先改密。

cookie token 仅在客户端持有，数据库 `user_sessions` 存储其 SHA-256 摘要、CSRF token、用户版本及到期时间。重启不丢会话；到期时间为 12 小时。注销撤销当前会话，改密或管理员更新用户使旧会话失效。

新建 Key、启用和转移归属按 quota 校验，停用或删除的 Key 不占启用名额（详见下方 quota 规则）。刷新仅替换密钥哈希，保留 ID、前缀、历史记录和调度信息。禁用用户会同时阻止其 Key 认证。

## Google OAuth

在 Google Cloud 创建 Web application OAuth client，登记完整回调地址（路径 `/auth/google/callback`），然后在 `/admin/google` 填写 Client ID、Secret 和回调地址并启用。生产环境使用 HTTPS 地址；本地开发可使用 localhost。允许邮箱域留空意味着允许所有经过 Google 验证的邮箱。

授权码通过服务器直接向 Google 换取 token，再请求 userinfo 并验证 email_verified。state 绑定浏览器 cookie、限时且只能使用一次，并使用 PKCE。参考：[Google Web Server OAuth 文档](https://developers.google.com/identity/protocols/oauth2/web-server)。当前自动化测试使用模拟 Google 响应；真实 Google 登录需要实际 OAuth 配置。

## 用量与价格

输入和输出价格单位均为 USD / 1M tokens。按请求模型名称精确匹配，模型别名需单独维护。每笔记录保存价格与费用快照，改价不修改这些快照；独立财务报表使用最新价格重算历史 Token 对应金额。未配置价格的请求明确标记为未定价，不按零价伪装为已计费。

费用 = (输入 tokens × 输入单价 + 输出 tokens × 输出单价) / 1,000,000。

月度节约金额 = 已定价 API 用量金额 − 当月全部 Worker 订阅成本。成本需手动录入，未录入时不显示节约金额。现有上游接口仅提供总输入/输出 tokens，因此不另算缓存或推理 token 价格。

详单保存请求 JSON（包含提示词），不保存 Authorization 请求头和 cookie。有效身份的参数校验、调度失败及中断请求也会记录；认证失败的请求不写入个人详单。历史请求没有原始参数时显示“历史请求未记录参数”。

## 升级

默认 `auto_create_schema=true` 时自动创建新表及添加旧表字段。当前项目的旧管理员迁入用户表，配置中的管理员成为 superadmin；旧 Key 归属该管理员，既有 Key 保留，新建、启用与转移适用 quota 名额限制。旧管理员表保留用于兼容迁移，新认证只读取用户表。已有签名式会话需重新登录一次，此后会话落库并支持重启保留。

部署前备份数据库和应用目录，仅重建 gateway 服务，Worker 转发器、容器和工作区不需更新。旧代码可在新增字段仍存在时回滚；回滚后需重新登录，旧管理员表不会同步本次升级后的改密。

## 测试

使用独立 PostgreSQL 测试库，避免写入生产数据：

```bash
createdb codex_gateway_feature_test
CODEX_GATEWAY_DATABASE_URL=postgresql+asyncpg:///codex_gateway_feature_test pytest -q
```

mock 模式测试通过 fixture 模拟 Worker manager 的工作区接口，实际转发调度实现保持原样。

## 财务报表更新

`/admin/finance` 现为价格配置，`/admin/reports` 为独立财务报表，支持按 UTC 月份或全部时间查看。报表按最新模型价格重新计算总量、用户/Key 和 Worker 维度金额，不使用或更新请求记录中的历史费用快照。未定价请求单独计数，免费模型（明确配置零价）视为已定价。用户归属采用请求发生时的归属，Worker 金额表示承载流量的 API 等价金额。全部时间成本仅汇总已录入的订阅月份。本期不实施预算限额。

## Key quota 与贡献 Worker

当前版本将旧的“每用户最多一个 Key”替换为启用名额：总 quota = 管理员授予额度 + 当前有效付费 Worker 数。新用户初始为 0；创建和启用占用一个名额，停用和删除释放名额。刷新密钥不影响额度。所有创建、启用、Key 归属调整与 Worker 额度变化使用 PostgreSQL 事务锁串行校验，防止并发超额。

管理员在用户列表的“增加额度”弹窗授予名额；`/account` 显示总额、来源、已启用数和可用数，支持多 Key 的创建、刷新、停用、启用及删除。额度不足时先停用从未使用的 Key，再按最近使用时间从远到近停用；并列时按创建时间和 ID 排序。恢复额度不会自动启用之前停用的 Key。

`/workers` 为贡献 Worker 页面。普通用户仅能管理自己拥有的 Worker，管理员可管理全部并调整归属。普通用户创建的 Docker 名称由服务器随机生成，避免重用其他人的容器名或遗留卷。账号读取仅向所有者与管理员显示邮箱、认证类型和套餐，不返回 token。Worker 归属保存在 `workers.owner_username`，与 Docker 创建请求的登录用户一致；迁移时现有 Worker 全部归属配置中的管理员。

启用、ready/busy、已经读取到 ChatGPT 付费套餐（plus/pro/team/business/enterprise/edu）的 Worker 提供 1 个名额；free、未知套餐、API Key 认证、未登录、异常、停用和删除均不提供。重复检测不累加名额。账号检测后台按 `worker_recovery_interval_seconds` 周期运行（默认 30 秒，最多 4 个并发），退出登录和外部容器失效会在检测后撤销贡献额度。转发器既有的隔离/恢复状态变更也同步校验额度；没有改动请求转发和调度算法。Worker 恢复健康付费状态后额度自动恢复。转移 Worker 会在同一事务中重算原、新所有者的额度。

升级只执行一次：为当前每位用户的已启用 Key 数补齐基础授予额度，保留现有使用；新用户仍从 0 开始。重复启动不会重复赠送额度。预算/金额限额不在本期范围。

测试库 `codex_gateway_quota_isolated_20260926` 和迁移验证库 `codex_gateway_quota_upgrade_20260926` 与本地预览、线上数据库完全独立。

普通用户创建 Worker 时，名称前缀固定为实际用户名加 `-worker-`，默认数字后缀从 `01` 递增，可填写 1–2 位 ASCII 数字（范围 01–99，自动补齐两位）。已删除或转移的名称仍保留，避免重用；自动序号超过 99 时可选择未使用的序号。Docker 内部标识仍由服务端独立生成。

普通用户名下存在未登录或尚未确认登录的 Worker 时，必须先完成登录并探测，或删除该 Worker，才能新增。已确认登录的免费账号也允许继续创建，但不提供贡献额度。后端按用户串行检查创建请求，防止并发绕过；管理员不受上述命名和新增限制。

模型快捷名 `codex` 已取消。客户端请直接使用 `/v1/models` 返回的模型名，例如 `gpt-6-sol`。旧环境变量 `CODEX_GATEWAY_MODEL_NAME` 不再生效；`CODEX_GATEWAY_UPSTREAM_MODEL` 仍用于 Worker 健康探测。历史请求和计价记录保留。

价格配置新增订阅套餐月费（USD / Worker / 月）：自动发现并持久保存 Worker 的套餐名称，也可通过弹窗手动新增；名称去除首尾空格并统一小写。未配置价格不视为免费，免费套餐应明确填写 0。

价格配置和财务报表展示当前已登录 Worker 的月费估算。按 Worker 数量计费，包含超限额、停用但仍登录的 Worker，排除已退出登录、未登录、已删除的 Worker。同一账号在多个 Worker 登录按多个 Worker 计算。连接失败时沿用最近确认的账号信息；账号检测确认退出后排除。未识别套餐或未定价的 Worker 单独提示，总费用标为不完整。该实时估算不覆盖历史月份手工录入的实际订阅成本，也不会改动请求计价快照。

财务报表顶部的本月订阅成本与节约金额使用当前已登录 Worker 和最新套餐月费实时重算，不再读取本月手工成本；全部时间汇总过去月份已录入的成本与本月实时成本（不重复计入本月手工成本，不包含未来月份）。历史月份仍使用当时手工录入的成本。当前有未定价 Worker 时不显示不完整的节约金额。

邮箱型用户名使用邮箱前缀，例如 `alice@example.com` 的 username 为 `alice`，完整邮箱仍保存在 email 字段。Google 新用户和管理员使用完整邮箱创建的用户均遵循该规则；非邮箱本地用户名（例如 admin）保持不变。相同前缀冲突返回提示，不会自动绑定或合并不同身份。密码登录支持用户名，也兼容完整邮箱精确匹配；不会仅凭输入邮箱的前缀选择账号。

升级将事务性迁移现有邮箱型 / Google 用户的用户名，并同步会话、Key、Worker、历史用量及旧管理员表引用；Worker 规范显示名称同步更新，容器标识与卷保持不变。已有会话和 Key 无需重建。迁移发现重名时整体取消，需先处理冲突。

普通用户完成密码登录或 Google 登录后进入 `/overview` 自助服务概览（首次强制改密仍先进入我的账户）。概览展示使用说明、三步准备进度及“贡献 Worker → 生成 Key → 定期维护”状态卡片，所有数据仅查询当前用户名下未删除的资源；异常、超限、停用、未登录分别提示处理。所有 Worker 都已确认登录且启用、状态正常才显示“一切正常”。所有用户页面共享自助服务概览导航入口。

贡献额度按“归属用户名 + 登录账号完整邮箱”去重，邮箱忽略大小写和首尾空格。同一用户名下，同一付费账号无论登录多少个健康且启用的 Worker，都只提供 1 个名额；不同用户分别计算。无法读取邮箱时不授予贡献额度。删除、停用或退出某个 Worker 后，只要同账号仍有其他符合条件的 Worker，就保留该名额。页面标注重复账号；账号或归属变化、后台检测以及应用启动时均重新执行额度限制，超额 Key 按最久未使用顺序停用。管理员授予额度不受去重影响。

已登录 Worker 的“重新登录”在概览与贡献 Worker 页面均先弹出确认。取消时不发送请求；确认后，通过同一 WebSocket 连接依次执行 account/read、account/logout（params 为 null）、account/login/start。退出失败不会继续登录；退出成功后即清除本地账号状态并重算贡献额度，即使后续新登录失败也保留该状态。重复账号仍有其他有效 Worker 时保留其贡献额度。

贡献额度不再使用套餐白名单：套餐名称去除首尾空格并忽略大小写后，只要非空且不是 free，就按非免费套餐计算，包括 self_serve_business_prolite 和后续新增套餐。未识别套餐仍不提供额度；登录、健康、启用及同用户账号去重条件保持有效。

个人 Key 表格将脱敏前缀放入独立列，操作按钮放在单元格内部，保持行线对齐。贡献 Worker 页面与管理员概览显示账号 5 小时 / 周窗口剩余百分比、重置时间（浏览器本地时区）和读取时间，加载页面自动读取，也可手动刷新。通过 account/rateLimits/read 只读查询，按 windowDurationMins 区分 300 分钟和 10080 分钟，支持多个额度桶；缺失窗口显示暂无数据。查询失败不改变 Worker 状态或 Key quota，普通用户仅能查询自己的 Worker。
