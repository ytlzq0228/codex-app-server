# 管理概览监控

管理概览只展示汇总与监控面板；API Key、Worker 明细位于各自管理页面。

套餐配置增加正数 `weight`（默认 1，最多六位小数）。订阅池按仍登录、未删除的 Worker 统计，包含停用及隔离记录，同账号的多个 Worker 分别计算。每个 Worker 在同类额度桶中取最大已用比例，综合风险再取 5 小时、周窗口中的最大值。池用量为 `Σ(权重 × 已用比例) / Σ有效样本权重`。未知套餐用权重 1；读取成功但缺失窗口按不限额（用量 0%）计入；读取失败仍排除，并记录样本数和权重覆盖率。用量快照版本 3 在版本 2 聚合口径上增加逐 Worker 周用量与加权剩余值，版本 1/2 历史继续保留；旧版采样不参与逐 Worker 额度排序，下一小时更新。三个当前指标使用进度条显示已用比例，未知数据使用斜纹底色。它是重置窗口不对齐的风险估计，不是账单用量或统一周期消耗量。

Worker 五类状态互斥，分母包含数据库所有 Worker 记录：

- 完全正常：已登录、启用，状态 ready/busy，无故障。
- 登录但超限隔离：error + limit。
- 登录但服务异常隔离：error + connection/runtime。
- 未登录：无认证方式或 logged_out。
- 其他异常：其余情况，包括已删除的保留记录、停用、排空、未知故障。

后台随网关启动，不依赖页面访问：Worker 每 10 分钟、用量每小时存储一个 UTC 时间桶。启动落在桶中间时记录实际采样时间；停机期间留空，不填补虚构历史。页面状态实时查询，当前用量来自最近小时采样，超过两小时标记过期。历史可查看最近 1/7/30/90 天；前端每分钟刷新，时间按浏览器本地时区显示。

采用通用 `metric_snapshots` 表，联合主键 `(metric, bucket_at)`，另外保存 `observed_at` 和带 `version` 的 JSON `payload`。每类指标独立定义频率与 payload；用量快照保存当时权重、覆盖情况和每个 Worker 的周使用率/加权剩余额度，配置变动不重算旧快照。PostgreSQL 事务级 advisory lock 防止多实例重复读取，唯一主键保证落库幂等。用量读取并发为 4，单个超时 25 秒，一轮最多 55 秒；失败及超时样本作为缺失处理，不改变 Worker 状态。单次失败会记录日志并在下一轮重试。

池化新会话和安全故障转移按同一优选顺序调度：先选择当前正在占用的 WS 最少的 Worker；连接数相同时，选择最近两小时内采集到的周加权剩余额度 `(100 - 周已用百分比) × 套餐权重` 最大者；再次相同时才使用 `prompt_cache_key` 亲和顺序或随机顺序。额度读取失败不伪造剩余值，在连接数相同的情况下排在有有效周数据的 Worker 后面。固定 Worker、显式会话绑定和待返回工具结果不参与池排序。

新增快照存储是必要的，因为当前账号额度及 Worker 状态会覆盖，无法从请求流水重建。今后类似瞬时状态统计可复用此表；财务按天、请求量按天等可从带时间的原始事件聚合，无需重复存快照。当前不自动清理历史；日增长约 168 行（144 个状态点 + 24 个用量点）。如未来引入维度或保留策略，再按实际查询需求扩展。

默认 `auto_create_schema` 启动流程创建新表，并为已有套餐增加默认权重；关闭自动建表的部署应先执行等效迁移。
