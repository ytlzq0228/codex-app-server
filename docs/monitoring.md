# 管理概览监控

管理概览只展示汇总与监控面板；API Key、Worker 明细位于各自管理页面。

套餐配置增加正数 `weight`（默认 1，最多六位小数）。订阅池按仍登录、未删除的 Worker 统计，包含停用及隔离记录，同账号的多个 Worker 分别计算。每个 Worker 在同类额度桶中取最大已用比例，综合风险再取 5 小时、周窗口中的最大值。池用量为 `Σ(权重 × 已用比例) / Σ有效样本权重`。未知套餐用权重 1；缺失或读取失败不计为零，并记录样本数和权重覆盖率。它是重置窗口不对齐的风险估计，不是账单用量或统一周期消耗量。

Worker 五类状态互斥，分母包含数据库所有 Worker 记录：

- 完全正常：已登录、启用，状态 ready/busy，无故障。
- 登录但超限隔离：error + limit。
- 登录但服务异常隔离：error + connection/runtime。
- 未登录：无认证方式或 logged_out。
- 其他异常：其余情况，包括已删除的保留记录、停用、排空、未知故障。

后台随网关启动，不依赖页面访问：Worker 每 10 分钟、用量每小时存储一个 UTC 时间桶。启动落在桶中间时记录实际采样时间；停机期间留空，不填补虚构历史。页面状态实时查询，当前用量来自最近小时采样，超过两小时标记过期。历史可查看最近 1/7/30/90 天；前端每分钟刷新，时间按浏览器本地时区显示。

采用通用 `metric_snapshots` 表，联合主键 `(metric, bucket_at)`，另外保存 `observed_at` 和带 `version` 的 JSON `payload`。每类指标独立定义频率与 payload；用量快照保存当时权重和覆盖情况，配置变动不重算旧快照。PostgreSQL 事务级 advisory lock 防止多实例重复读取，唯一主键保证落库幂等。用量读取并发为 4，单个超时 25 秒，一轮最多 55 秒；失败及超时样本作为缺失处理，不改变 Worker 状态。单次失败会记录日志并在下一轮重试。

新增快照存储是必要的，因为当前账号额度及 Worker 状态会覆盖，无法从请求流水重建。今后类似瞬时状态统计可复用此表；财务按天、请求量按天等可从带时间的原始事件聚合，无需重复存快照。当前不自动清理历史；日增长约 168 行（144 个状态点 + 24 个用量点）。如未来引入维度或保留策略，再按实际查询需求扩展。

默认 `auto_create_schema` 启动流程创建新表，并为已有套餐增加默认权重；关闭自动建表的部署应先执行等效迁移。
