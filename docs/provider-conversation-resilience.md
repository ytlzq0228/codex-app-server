# Claude / Gemini 会话恢复与工具兼容

## 问题与处理原则

本轮梳理区分三个动作：继续已认证的挂起工具、取消旧执行后重建、仅使用客户端提交历史回答。工具失败或历史不再适合续接，不应永久阻塞用户下一轮消息。

- 已认证结果仍要求 API Key、逻辑会话、call_id 与当前执行一致。工具排序和描述变化可接收，挂起 Worker 保留原 alias 映射。
- 新用户轮次允许取消旧挂起执行；历史缺失、改写、空检查点和缺失工具结果可转为新的无工具回答。不把这种历史当作续接凭据。
- 自动处理过期工具结果或工具契约变化，需要明确会话身份及匹配的持久化检查点；入口校验通过后仍在执行锁内重检响应标识，防止竞争。
- 恢复轮禁用工具及 additional_tools，并明确说明旧执行不可续接、历史可能不完整、无结果工具完成状态未知。下一用户轮次可重新使用当前工具。
- 跨节点取消由所属节点确认；鉴权失败、身份不匹配、结果已经被其他请求领取、所有者不可用或取消超时，不启动第二个执行。
- provider 权限、跨账号隔离、JSON Schema / grammar 校验、Worker 安全策略保留。一次恢复不能保证底层模型或网络必然可用。

## 协议修正

Claude Code 2.1.288 的实际 --bare 请求尾部包含空 system 数组，按空提醒处理；有内容提醒保留。工具结果后新用户消息再附 system/developer 提醒时，使用实际对话末尾判断新轮次。

Gemini 原生同一个 content 中 functionResponse 与用户文本按原顺序转换。Responses 工具结果 is_error 透传 Worker。两个 provider 的尾部提醒均可随工具结果传入。

## 验证方式

自动化测试覆盖：JSON 格式兼容、拒绝后继续、空检查点、摘要历史、缺失结果、工具配置改变、过期结果、陈旧响应竞争、API Key/会话/节点隔离、取消超时、已领取结果保护、排队状态重检、无工具恢复、原生消息顺序及错误结果透传。

真实验证使用本机 Claude Code 2.1.288、Gemini CLI 0.61.0，隔离配置目录和临时测试 Key。仅操作专用测试文件。scripts/validate_provider_resilience.py 提供可重复的真实模型矩阵，lookup 返回固定字符串，不执行模型生成的命令。seed 阶段创建挂起工具，重启测试网关后 verify 验证遗失执行恢复。

现有 Gemini CLI 本次观测请求没有明确 thread ID，普通请求按完整输入新建底层会话，活跃工具通过已认证 call_id 续接。没有可靠身份或检查点的过期结果不会伪造匹配；用户发送新消息时可继续。自动重复结果的响应缓存、网络分区后的强制恢复、未知版本所有辅助模板不在本轮保证范围内。

## 发布与观测

仅测试环境验收；正式环境另行发布。恢复审计记录 execution.action=new_thread、reason=context_only_recovery，原始输入保留审计。以恢复后成功轮次、重复调用次数及后续工具可用性判断效果，不只统计 HTTP 409 数量。

本文件描述实现与验收方法；实际通过数量和测试环境版本应以本次验收报告为准。


## 2026-10-06：Claude 长工具链超时与失败结果重试

Claude Worker 原先对整条工具链累计扣除 300 秒推理预算，即使持续输出或多次成功往返工具也会耗尽。现在使用三个独立上限：300 秒无进展、单段推理 1800 秒、整次底层执行 14400 秒。有效输出刷新无进展计时；已认证工具结果返回后重置推理阶段计时；等待客户端工具期间暂停推理阶段检查，但保留工具自身 TTL 和总执行上限。心跳不会刷新进展计时。

已认证的 Claude 工具续接失败时，保留该次输入的历史指纹（包括工具结果），标记为 tool_execution_failed。相同身份、相同端点、完整匹配输入的重试，可转成无工具的上下文恢复回答；不会重新提交旧工具 RPC。恢复在路由前识别，并在执行行锁内再次核对响应标识和历史。活跃租约、跨账号/会话、内容改写以及显式 previous_response_id 保留原校验。更早版本已清除的失败检查点无法追溯恢复，需发送新用户消息。

此次变更需要同时发布 gateway 和 Claude Worker 镜像；只更新 gateway 不会改变现有 Worker 的超时计时。现有运行中的 Worker 也需按运维流程更新。


### Codex 上下文压缩与跨节点错误

带完整已验证历史、待处理工具结果和新用户消息的压缩请求，可以省略或清空工具定义。
网关先确认原工具执行取消，再用请求自身配置创建新线程；不继承旧工具，也不重复提交旧工具结果。
显式修改工具定义或模型仍被拒绝；已认领的结果不能被取消。
跨节点取消保留 owner 返回的结构化 400/409/422；网络失败、无效确认和服务端异常仍按取消未确认处理，禁止启动新执行。
